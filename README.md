# Smart Exam Bot

بوت Telegram عربي للاختبارات الإلكترونية، مبني باستخدام Python 3.12 وAiogram 3 وSQLAlchemy 2. يدعم SQLite للتجربة المحلية وPostgreSQL للإنتاج، مع إعداد Docker وRailway.

> **حالة الإصدار:** هذه حزمة إصدار أول قابلة للتشغيل وتنفّذ مسار الاختبار الأساسي من الإنشاء إلى النتيجة، مع إدارة المجموعات والمواضيع والاستفتاءات. ليست جميع البنود المتقدمة الواردة في وثيقة المتطلبات منفّذة في هذا الإصدار؛ راجع قسم «حدود الإصدار الحالي» قبل النشر العام.

## 1. المتطلبات

- Python 3.12 أو أحدث.
- حساب Telegram وإنشاء بوت عبر BotFather.
- رقم Telegram ID للمالك الرئيسي.
- PostgreSQL للإنتاج. SQLite يعمل للتجربة المحلية.
- Redis اختياري لحفظ جلسات FSM خارج ذاكرة عملية البوت.

## 2. التشغيل المحلي على Windows

افتح PowerShell داخل مجلد المشروع:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

افتح ملف `.env` وضع:

```env
BOT_TOKEN=توكن_البوت_من_BotFather
OWNER_ID=رقم_Telegram_ID_الخاص_بك
DATABASE_URL=sqlite+aiosqlite:///./smart_exam_bot.db
REDIS_URL=
BOT_MODE=polling
LOG_LEVEL=INFO
PORT=8080
```

لا تشارك ملف `.env` مع أحد ولا ترفعه إلى GitHub.

نفّذ ترحيل قاعدة البيانات ثم شغّل البوت:

```powershell
alembic upgrade head
python -m app
```

يعمل خادم فحص الحالة على `http://127.0.0.1:8080/health`.

## 3. التشغيل على Linux / macOS

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
# عدّل BOT_TOKEN وOWNER_ID داخل .env
alembic upgrade head
python -m app
```

## 4. إنشاء Telegram Bot Token

1. افتح Telegram وابحث عن الحساب الرسمي `@BotFather`.
2. أرسل `/newbot` واتبع خطوات اختيار الاسم واسم المستخدم.
3. انسخ الرمز الذي يصدره BotFather وضعه في `BOT_TOKEN` داخل `.env` أو متغيرات بيئة الاستضافة.
4. افتح محادثة البوت الجديد وأرسل `/start` إلى البوت.
5. استخرج Telegram ID الخاص بك من أداة موثوقة لعرض رقم الحساب، وضع الرقم في `OWNER_ID`. يعتمد النظام على الرقم لا على Username.

لا تضع الرمز في كود Python أو رسالة عامة. إذا انكشف الرمز، ألغِه من BotFather وأنشئ رمزاً جديداً.

## 6. أوامر الإدارة

تُمنح صلاحية الإدارة للمالك تلقائياً. يستطيع المالك منح دور `admin` لمستخدم بدأ البوت مسبقاً:

```text
/grant TELEGRAM_ID admin
/grant TELEGRAM_ID user
```

أوامر أخرى:

| الأمر | الوظيفة |
|---|---|
| `/panel` | لوحة الإدارة |
| `/dev` | لوحة المالك الرئيسية |
| `/newexam` | إنشاء مسودة اختبار في الخاص |
| `/addq EXAM_ID` | إضافة سؤال اختيار من متعدد |
| `/publish EXAM_ID` | نشر الاختبار في المجموعة/الموضوع الحالي |
| `/settopic اسم_الموضوع` | تسجيل الموضوع الحالي |
| `/export EXAM_ID` | تصدير نتائج الاختبار إلى CSV |
| `/stats` | إحصائيات النظام (المالك فقط) |
| `/owner` | طلب مساعدة المالك من مجموعة |
| `/reply REQUEST_ID نص` | رد المالك على صاحب طلب المساعدة من الخاص |
| `/grant ID admin` | منح صلاحية مشرف (المالك فقط) |
| `/block ID` و`/unblock ID` | حظر مستخدم أو رفع الحظر |
| `/backup` | إرسال نسخة احتياطية للمالك |
| `/broadcast نص` | إرسال إعلان لمن فعّل الاشتراك فقط |

### إنشاء اختبار

1. افتح الخاص مع البوت واستخدم `/newexam`.
2. أدخل عنوان الاختبار والوصف والمدة ونسبة النجاح.
3. استخدم `/addq EXAM_ID` لإضافة سؤال.
4. أرسل نص السؤال.
5. أرسل الخيارات، كل خيار في سطر مستقل.
6. أرسل رقم الإجابة الصحيحة.
7. أدخل الدرجة ثم الشرح، أو `-` لتخطي الشرح.
8. كرر `/addq` لإضافة أسئلة أخرى.
9. أضف البوت إلى المجموعة المطلوبة، ثم استخدم `/publish EXAM_ID` داخل المجموعة أو الموضوع المطلوب.
10. ينشر البوت رابطاً خاصاً بالمشاركة. يبدأ الطالب الاختبار في الخاص، وتُحفظ كل إجابة في قاعدة البيانات.

الصح والخطأ متاحان عبر سؤال بخيارين مثل «صح» و«خطأ».

### الاستفتاءات

داخل مجموعة Telegram:

```text
/poll ما رأيك بالمحاضرة؟ | ممتازة | جيدة | تحتاج تحسين
/pollna هل حضرت الدرس؟ | نعم | لا
/quizpoll عاصمة العراق؟ | بغداد | البصرة | الموصل
```

`/poll` مجهول، و`/pollna` غير مجهول، و`/quizpoll` ينشئ Telegram Quiz Poll ويعتبر الخيار الأول صحيحاً. لا يخزّن النظام هوية المصوتين في الاستفتاءات المجهولة. أوامر الاستفتاء في هذا الإصدار تعمل داخل المجموعات؛ نشر الاستفتاءات إلى القنوات غير مفعّل بعد.

## 7. دعم Forum Topics

- عند وصول حدث إنشاء موضوع جديد إلى البوت، يحفظ النظام `chat_id` و`message_thread_id` واسم الموضوع.
- استخدم `/settopic اسم` من داخل الموضوع لتسجيل موضوع قديم يدوياً.
- عند نشر اختبار داخل موضوع، يستخدم البوت `message_thread_id` نفسه لإرسال الإعلان.
- تحفظ حالة الإغلاق وإعادة الفتح عند وصول تحديثات Telegram ذات الصلة.

**قيد Telegram Bot API:** لا توجد طريقة عامة في Bot API لسرد كل المواضيع القديمة في المجموعة. لذلك لا يكتشف هذا المشروع جميع المواضيع القديمة تلقائياً؛ يجب تسجيل الموضوع القديم من داخله بواسطة `/settopic` أو انتظار حدث إنشائه. راجع توثيق Telegram الرسمي: https://core.telegram.org/bots/api

## 8. إعداد Railway

1. ارفع مجلد المشروع إلى مستودع GitHub خاص.
2. أنشئ مشروعاً جديداً في Railway واختر Deploy from GitHub Repo.
3. أضف خدمة PostgreSQL إلى المشروع.
4. في خدمة البوت، أضف المتغيرات التالية:

```env
BOT_TOKEN=...
OWNER_ID=...
DATABASE_URL=${{Postgres.DATABASE_URL}}
BOT_MODE=polling
LOG_LEVEL=INFO
APP_VERSION=1.0.0
```

استبدل `Postgres` باسم خدمة PostgreSQL الفعلي في مشروعك عند إنشاء Reference Variable من واجهة Railway. لا تضع `REDIS_URL` إلا إذا أضفت Redis وربطت متغيره.

5. تأكد أن Railway يستخدم Dockerfile الموجود في جذر المستودع. ملف `railway.toml` يضبط مسار فحص الحالة وسياسة إعادة التشغيل.
6. اجعل عدد نسخ خدمة البوت نسخة واحدة؛ يوجد قفل PostgreSQL احتياطي لمنع تشغيل أكثر من عملية Long Polling بالرمز نفسه.
7. راقب Logs حتى تنتهي عملية `alembic upgrade head` ويبدأ البوت.
8. اختبر `/start` في Telegram، ثم افتح `/health` على عنوان الخدمة إذا أنشأت نطاقاً عاماً.

Railway يوفّر `DATABASE_URL` لخدمة PostgreSQL. فحص Health Check يُستخدم للتحقق من جاهزية النشر الجديد ولا يعني مراقبة مستمرة بعد تفعيل النشر؛ التطبيق يسجل أخطاءه بنفسه. راجع: https://docs.railway.com/databases/postgresql وhttps://docs.railway.com/deployments/healthchecks

### ملفات النشر

- `Dockerfile`: يبني صورة Python 3.12 ويثبت المتطلبات و`postgresql-client` لنسخ PostgreSQL الاحتياطية.
- `railway.toml`: يحدد Dockerfile و`/health` وسياسة إعادة التشغيل.
- `docker-compose.yml`: تشغيل محلي مع PostgreSQL وRedis.
- `.env.example`: نموذج متغيرات البيئة.

## 9. النسخ الاحتياطي والاستعادة

- للنسخة اليدوية، استخدم `/backup` في الخاص مع البوت كمالك.
- مع SQLite يرسل البوت ملف قاعدة البيانات.
- مع PostgreSQL يستخدم `pg_dump` ويرسل ملفاً بصيغة custom dump.
- الاستعادة من PostgreSQL تتم بأداة `pg_restore` على قاعدة بيانات مستهدفة بعد أخذ نسخة أخرى منها. لا تستعد فوق قاعدة إنتاج دون التأكد من الهدف.
- ملف النسخة الذي يرسله البوت لا يُحفظ تلقائياً في تخزين دائم داخل حاوية Railway؛ نزّله واحفظه في مكان آمن مستقل.

## 10. الاختبارات البرمجية

```bash
pip install -r requirements-dev.txt
pytest -q
python -m compileall app migrations
```

هذه اختبارات وحدات وفحص ترجمة Python. يجب أيضاً إجراء اختبار فعلي من حساب Telegram ومن مجموعة Topics حقيقية قبل إتاحة البوت للجمهور؛ لا يمكن اختبار صلاحيات Telegram أو النشر إلى مجموعتك دون بيانات البوت والمجموعة الفعلية.

## 11. حدود الإصدار الحالي

موجود في هذا الإصدار:

- إنشاء اختبارات مسودة وإضافة أسئلة اختيار من متعدد.
- الصح والخطأ باستخدام خيارين.
- نشر الاختبار في مجموعة/موضوع أو قناة محددة بواسطة أمر المالك/المشرف، ورابط مشاركة فردي عبر `/start`.
- حفظ المحاولات والإجابات والتصحيح واحتساب النجاح والمهلة الزمنية، مع قيد قاعدة بيانات يمنع وجود محاولتين نشطتين للمستخدم نفسه في الاختبار نفسه.
- خلط ترتيب الأسئلة والخيارات لكل محاولة مع حفظ الترتيب لإعادة الاستكمال بعد إعادة التشغيل.
- استعادة المحاولات بعد إعادة تشغيل البوت، وإنهاء المحاولات المنتهية دورياً.
- تسجيل مواضيع Forum عند وصول تحديث Telegram أو باستخدام `/settopic`.
- الاستفتاءات العادية والمجهولة وغير المجهولة وQuiz Poll.
- دور المالك ودور مشرف عام بسيط، والحظر وسجل التدقيق لبعض عمليات الإدارة، وطلبات استدعاء المالك والرد عليها عبر `/reply`.
- لوحة أزرار أولية، إحصائيات، Leaderboard، تصدير CSV ونسخ احتياطي يدوي.
- PostgreSQL وSQLite وAlembic وRedis الاختياري وDocker وRailway وHealth Check.

غير مكتمل بعد ويحتاج مرحلة تطوير مستقلة:

- الأسئلة متعددة الإجابات والإجابة النصية القصيرة والتصحيح اليدوي.
- إرفاق صور السؤال وملفات الغلاف.
- Excel/XLSX وJSON/CSV لاستيراد بنك الأسئلة، وتصدير XLSX.
- صلاحيات RBAC دقيقة لكل مجموعة ولكل قسم، وأدوار Developer وGroup Manager وExam Manager بواجهات مستقلة.
- جداول زمنية متقدمة لبداية الاختبارات ونهايتها، وسياسة محاولات قابلة للتخصيص من لوحة التحكم، وإعدادات خلط الأسئلة والخيارات.
- لوحة متقدمة لإدارة جميع القنوات والمجموعات والمواضيع وسردها.
- نشر الاستفتاءات إلى القنوات، واستفتاءات بجدولة وإغلاق تلقائي كامل وإحصائيات تحليلية متقدمة.
- Webhook. الإصدار الحالي يرفض `BOT_MODE=webhook` بوضوح ويعمل بـ Long Polling.
- النسخ الاحتياطي المجدول إلى تخزين خارجي واستعادة مؤتمتة.

هذه الحدود موضحة حتى لا يُفهم أن كل ميزة في وثيقة الطلب قد نُفذت واختُبرت. لا يمكن ضمان منع الغش بصورة مطلقة؛ ما يقدمه هذا الإصدار هو حفظ مركزي وتحقق من الإجابات والمحاولات وتقليل فرص التلاعب.

## 12. الدعم والملاحظات

- إذا ظهر `Conflict: terminated by other getUpdates request`، أوقف النسخة الأخرى وتأكد أن Railway يشغل Replica واحدة فقط.
- إذا لم تصل رسائل المجموعة، راجع Privacy Mode وصلاحيات البوت.
- إذا فشل نشر القناة، أضف البوت مشرفاً وامنحه صلاحية نشر الرسائل.
- لإدارة المواضيع وإنشائها من البوت يلزم منحه `can_manage_topics`؛ أما النشر العادي داخل موضوع موجود فيحتاج صلاحية إرسال الرسائل المناسبة.
- لا تشارك Token أو رابط اتصال قاعدة البيانات في لقطات الشاشة أو المحادثات العامة.
